# Phase 4B.14 — Appropriate Content Formats

Date: July 27, 2026  
Status: Implemented without new routes

## Format decision

The existing page system already uses a varied answer architecture:

- concise definitions appear in visible service overviews;
- Coffee Bar and Sweet Cart choices use side-by-side decision cards;
- Weddings uses a chronological planning timeline;
- event and activation pages use ordered planning processes;
- Seating Rentals uses a quote-preparation checklist;
- Coffee Bar and Sweet Cart use confirmed inclusion lists;
- service pages provide visible event-fit and related-service links;
- confirmed capacity and simultaneous-setup limits use summary blocks;
- operational requirements use visible logistics summaries;
- gallery figures include contextual captions; and
- secondary or edge-case questions remain in contextual accordions.

## Priority commercial answers

The material gap was pricing. Coffee Bar, Sweet Cart, and Seating Rentals each
had a direct, accurate answer, but the answer was available only inside the
service FAQ accordion.

Each pricing answer now appears once in a visible cost-factor panel inside the
existing operational section. The panel:

1. asks the commercial question;
2. answers with the determining factors;
3. explains how Luxe confirms the scope; and
4. links directly to the inquiry step.

The pricing item is removed from the rendered service accordion, while the
remaining secondary questions stay there. The complete visible question set
continues to support matching FAQ structured data where already configured.

## Deliberate deviations

### Comparison tables

No comparison table was added. Current service comparisons involve only two or
three nuanced choices and already use visible side-by-side cards. Those cards
retain explanatory context and adapt to narrow screens more cleanly than a
dense table. A table becomes appropriate only when a stable set of three or
more options has several exact attributes that readers need to compare
row-by-row.

### Real event examples

No event example was invented. This format remains a content dependency until
Luxe has an approved event record containing accurate context, operating facts,
publishable photography, permission, and a useful outcome or planning lesson.

### Image captions

Existing gallery placeholders describe the intended service or setting context
and clearly record that approved photography is still required. Final captions
must be rewritten against the actual approved image and event; placeholder text
must not be presented as a real event example.

## Bloat controls

- No new route, resource article, broad comparison section, or location page was
  created.
- The visible pricing panels reuse existing approved answers rather than adding
  another version.
- Priority definitions, comparisons, inclusions, capacity, logistics, and cost
  factors remain outside accordions.
- Accordions remain reserved for secondary booking questions and edge cases.
